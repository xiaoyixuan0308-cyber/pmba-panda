# 引导提问

阶段 0 用它帮用户把一个想法或一段零散描述补成能写规格的输入；阶段 1c 追问真实案例时也会用到。

## 1. 提问原则

1. **一次只问一个问题。** 用户回答后再问下一个。一个话题要深挖，就拆成几个问题。
2. **能给选项就给选项。** 2–4 个选项，把推荐项放在第一位并写一句理由，同时说明用户可以自己写答案。
3. **用业务语言，不用技术词。** 问"谁可以修改已经批准的申请？"，不问"Approval 实体的 update 权限给哪个角色？"。
4. **先问具体案例，再问一般规律。** "讲讲上周处理的一单" 比 "你们的流程是什么" 更容易得到真实答案。
5. **复述确认。** 每问完一组（例如角色），用一两句话复述理解，请用户纠正。
6. **记录出处。** 用户的回答在规格中标 `[用户]`；由案例推出的标 `[案例: 编号]`。
7. **已经有材料的，先看材料再问。** 不要问材料里已经写清楚的事，只问材料里没有的、矛盾的或看不懂的。

---

## 2. 提问顺序

按下面顺序进行，前一组的答案会影响后一组的问题：

1. 目标与痛点
2. 现在怎么做、有哪些材料
3. 涉及的人
4. 一个真实案例（走一遍完整过程）
5. 业务量级与使用场景
6. 现有系统
7. 项目约束
8. 原型范围与规模档位

---

## 3. 问题库

每个问题给出：怎么问、可选项（如适用）、答案用在哪里。

### 3.1 目标与痛点

| 问法 | 选项示例 | 用在 |
|---|---|---|
| 你希望这个系统帮你解决的最主要问题是什么？ | 信息分散找不到 / 流程太慢要催 / 经常出错 / 没法统计 / 其他 | 00-brief、目标流程要说明解决了哪个痛点 |
| 现在这件事最让人头疼的是哪一步？ | （开放回答） | 01-as-is 的痛点标注 |
| 如果系统做好了，你怎么判断它有用？ | 处理时间缩短 / 出错减少 / 领导能看到进度 / 其他 | NFUS 和验收依据 |

### 3.2 现在怎么做

| 问法 | 选项示例 | 用在 |
|---|---|---|
| 这件事现在是怎么管的？ | Excel 表格 / 纸质单据 / 群聊和邮件 / 已有一个旧系统 / 主要靠人记 | 判断能挖哪些材料 |
| 方便把正在用的表格、单据或截图发给我吗？先把姓名、电话、金额等换成代号再发。 | — | 00-materials、1a 材料考古 |
| 这份台账是哪天导出的？ | — | 逐行核对的基准日 |
| 系统上线后，现有台账里的历史记录要导进来吗？ | 要，全部导入 / 只导入没结束的 / 不需要 | NFUS 数据迁移 |

### 3.3 涉及的人

| 问法 | 选项示例 | 用在 |
|---|---|---|
| 从头到尾，有哪些人会经手这件事？按岗位说就行，不用说名字。 | （开放回答） | 01-actors |
| {岗位A} 和 {岗位B} 能做的事有重叠吗？比如都能处理归还？ | 有重叠 / 完全不同 / 不确定 | 参与者泛化 |
| 有没有只看不改的人，比如领导只看统计？ | 有 / 没有 | 角色视角表、CRUD 矩阵 |
| 有没有外部的人参与，比如客户、供应商、其他部门？ | 有，会直接操作 / 有，但只是收通知 / 没有 | 参与者清单、权限范围 |

### 3.4 一个真实案例

| 问法 | 用在 |
|---|---|
| 讲一个最近处理过的、比较典型的案子：一开始是什么情况，之后每一步谁做了什么，最后结果如何？ | 01-processes、golden-cases |
| 这个过程中，哪一步需要等别人？一般等多久？ | 时间规则、超时例外 |
| 有没有哪一步需要多个人都同意？ | 并行（fork/join）或多级审批 |
| 再讲一个出了问题或比较特殊的案子。 | 例外路径、golden-cases |

追问方式：用户每说一步，就问"然后呢？"和"如果这一步不顺利会怎样？"，直到案子结束。

### 3.5 业务量级与使用场景

| 问法 | 选项示例 | 用在 |
|---|---|---|
| 大概每天或每月有多少单？ | 每天几单 / 每天几十单 / 每天上百单 / 不确定 | NFUS 性能 |
| 有没有特别忙的时间？ | 月底 / 学期初 / 节假日前 / 没有 | NFUS、时间相关例外 |
| 大家主要用什么设备操作？ | 电脑 / 手机 / 都有 | 界面设计、NFUS |
| 同时会有多少人在用？ | 几个人 / 十几人 / 更多 | NFUS |

### 3.6 现有系统

| 问法 | 选项示例 | 用在 |
|---|---|---|
| 这件事需要和公司里已有的系统打交道吗？比如财务、OA、企业微信、钉钉。 | 需要，要读取那边的数据 / 需要，要把结果推送过去 / 不需要 | 外部参与者、适配器 |
| 如果那个系统暂时连不上，现在你们怎么处理？ | （开放回答） | 外部系统失败的例外路径 |

### 3.7 项目约束

| 问法 | 选项示例 | 用在 |
|---|---|---|
| 系统里会存客户或员工的个人信息吗？ | 会，包括电话证件等 / 只有姓名 / 不会 | 00-constraints、NFUS 安全 |
| 记录需要保留多久？有规定吗？ | 有明确规定（几年） / 没规定但不能删 / 不确定 | 00-constraints、NFUS 数据保留 |
| 有没有必须遵守的行业规定或公司制度？ | 有（请简单说明） / 没有 / 不确定 | 00-constraints、BR |
| 有没有"某些人不能看某些数据"的要求？ | 有 / 没有 | CRUD 矩阵 |

### 3.8 原型范围与规模档位

| 问法 | 选项示例 | 用在 |
|---|---|---|
| 这个原型主要用来做什么？ | 给领导演示争取立项 / 自己内部试用 / 交给开发团队作参考 | 交付重点、评审摘要的写法 |
| 根据你说的，有 {N} 个核心流程、{M} 个角色，我建议用 {档位} 档。你看可以吗？ | 推荐档位 / 更精简 / 更完整 | 00-brief 规模档位 |
| 技术上用默认方案（本地一条命令就能运行的网页应用）可以吗？ | 可以 / 有指定要求 | default-stack |

## 4. 用户答不上来怎么办

- **给一个常见默认值，请用户确认**："很多团队的做法是……，你们也这样吗？" 确认前在规格中标 `[模式库]` 和 `[待确认]`。
- **换个问法**：抽象问题答不上来时，改成具体案例。"超时了怎么办"答不上来，就问"上一次有人拖着没处理，最后是怎么解决的？"
- **请用户去问人**：把问题记入待确认清单，并写成一句可以直接转发给同事的话。评审摘要会列出这些问题。
- **不要自己编答案**：任何猜测都必须标 `[推断]` 和 `[待确认]`。

## 5. 什么时候可以停止提问

阶段 0 满足以下条件即可进入阶段 1，不必一次问全：

- 知道核心流程有几个、各自的起点和终点
- 知道主要角色
- 至少有一个真实案例，或拿到了现有材料
- 项目约束已问过（答"没有"也算）
- 规模档位已确认
