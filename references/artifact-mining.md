# 材料考古

阶段 1a 使用。真实业务通常已经有一套"土办法"在运转，规则就藏在这些材料里。本文件规定如何从各类材料中系统地提取实体、属性、状态、角色、规则、例外和痛点。

## 目录

1. 开始之前
2. 按材料类型提取
3. 逐行核对
4. 提取时的注意事项
5. 输出格式

---

## 1. 开始之前

- **先检查隐私。** 打开每份材料后，先扫一遍有没有疑似真实个人信息：完整姓名配电话、身份证号、银行账号、住址、病历信息等。发现了就停下来，告诉用户具体在哪个文件、哪一列或哪一处，请用户脱敏后重新提供。不要继续读取或复述这些内容。
- **登记材料。** 在 `01-mining.md` 开头列出所有材料：编号（M1、M2……）、文件名、类型、用户对它的说明（谁在用、用来做什么）。
- **先问用途再读。** 如果用户没说，先问一句"这份表格平时是谁在填、谁在看？" 同一份 Excel，由前台填和由财务填，意义完全不同。
- **问清材料的时间点。** 问一句"这份台账是哪天导出的？"，记为核对基准日。第 3 节判断"是否已逾期""是否拖了很久"都以它为准，不要用今天的日期去推。

## 2. 按材料类型提取

### 2.1 Excel 台账

| 看什么 | 推出什么 | 举例 |
|---|---|---|
| 每个工作表 | 候选实体 | "借用登记"表 → `Loan` |
| 每一列 | 候选属性；按列中的值推断类型 | "借出日期"列 → `checkOutDate: Date` |
| 编号列 | 业务编号及其格式 | "JY-2026-001" → 业务编号格式 |
| 状态、进度、结果类的列 | 候选状态，统计出现过的所有值 | "待审 / 已批 / 已借出 / 已还" → 状态机候选状态 |
| 下拉选项 | 枚举值 | 部门下拉 → 部门枚举 |
| 大量为空的列 | 可选属性，或只在某些情况下才填（追问是什么情况） | "罚款金额"大多为空 → 只在逾期时填，对应例外 |
| 公式列 | 派生属性或计算规则 | `=IF(今天>应还日,"逾期","")` → 派生属性 `/isOverdue` 和一条 BR |
| 单元格颜色、批注 | 隐藏的状态或规则 | 标红的行 → 问"标红代表什么？" |
| 多个表里重复出现的列 | 实体之间的关联；也可能是重复录入的痛点 | 两个表都有"设备编号" → `Loan` 关联 `Equipment` |
| 备注列里的文字 | 例外和特殊处理 | "领导特批""先借后补单" → 例外，追问规则 |

### 2.2 纸质表单、申请单

| 看什么 | 推出什么 |
|---|---|
| 表单标题 | 候选实体或用例（"设备借用申请单" → 用例"Request Loan"） |
| 填写栏位 | 属性；标"*"或"必填"的是必填属性 |
| 勾选框 | 枚举值或布尔属性 |
| 签字栏、审批栏及其顺序 | 审批角色和审批顺序；多个签字栏并排可能是会签（并行） |
| "以下由某某填写""办公室专用"区域 | 不同角色负责的字段，对应 CRUD 矩阵 |
| 表单上的说明文字 | 业务规则（"借用期不超过 30 天" → BR） |
| 表单编号、版本号 | 是否存在多个版本、规则是否变过（追问） |

### 2.3 SOP、制度文件、操作手册

| 看什么 | 推出什么 |
|---|---|
| 编号的步骤 | 活动图中的动作及其顺序 |
| "由某某负责" | 泳道 |
| "必须""不得""只有……才能" | 业务规则 BR |
| "如果……则……""视情况" | 决策点；条件不止一个时考虑决策表 |
| "同时""分别""并行" | fork/join |
| 时限（"3 个工作日内"） | 时间触发、超时例外、NFUS |
| 附件中的表格模板 | 回到 2.1 / 2.2 处理 |

注意：SOP 写的是"应该怎么做"，不一定是"实际怎么做"。用真实案例核对，两者不一致时记为待确认，并写进现状流程的痛点。

### 2.4 邮件、群聊记录

| 看什么 | 推出什么 |
|---|---|
| 请示与批复（"这个能借吗？""可以"） | 审批环节和审批人 |
| 催办（"怎么还没处理？"） | 等待点、超时例外、痛点 |
| "先别动""等某某回来再说" | 隐藏的暂停状态或审批 |
| "这次特殊处理一下" | 例外，追问"什么情况下可以特殊处理？谁说了算？" |
| 反复出现的同类问题 | 痛点，或缺失的功能 |
| 转发、抄送给谁 | 需要收到通知的角色 |

### 2.5 现有系统截图

| 看什么 | 推出什么 |
|---|---|
| 菜单项 | 候选用例 |
| 列表页的列 | 属性 |
| 状态标签、筛选项 | 状态和枚举 |
| 按钮（审批、驳回、撤回） | 状态转换的触发 |
| 用户吐槽的地方 | 痛点 |

### 2.6 会议纪要、需求描述

- 提取方式与 SOP 类似，但要特别区分**已决定的事**和**讨论中的想法**。只有已决定的事可以作为规则，讨论中的想法标 `[待确认]`。

## 3. 逐行核对

第 2 节提取的是**结构**（有哪些列、哪些状态）。逐行核对看的是**实际发生了什么**：把台账、单据中的每一条记录拿已知规则检查一遍。真实业务中最有价值的发现往往在这里：规定没有被执行、执行的口径和规定不一样、有些情况一直没人处理。

**做法**

1. 先从制度文件、表单说明中列出所有能检查的规则（期限、费用、审批签字、必填项）。
2. 逐行检查每条记录，每行都写结论，即使是"符合"。检查内容包括：
   - **期限与日期**：天数是否在上限内；应还日期怎么算出来的（含不含当天），把算法写下来
   - **金额**：按规则重算一遍，与记录的金额是否一致
   - **审批**：按规则应该有的签字或审批，记录里有没有；还没轮到的审批不算缺失
   - **状态与日期是否吻合**：例如"已借出"但应还日期早于核对基准日，说明逾期没被发现
   - **未结记录**：以核对基准日检查所有没结束的记录，看有没有拖了很久没人处理的
3. 不符合的行归为三种之一：
   - **隐藏规则或例外**：规定里没写，但实际有一套做法（例如"先登记，等有设备再借"）
   - **执行与规定不一致**：规定这样写，实际那样做（例如规定只禁止"逾期未还"的人借用，实际以"有过逾期记录"为由拒借）
   - **漏办或拖延**：该做的事没做（例如逾期近一个月仍记为已借出）
4. "执行与规定不一致"一律列入矛盾清单，由用户裁决以哪个为准；不要默认规定一定对，也不要默认实际做法一定对。
5. **如果原型或新系统要导入这些历史记录**（阶段 0 问过数据迁移），每行再看一项：按新系统的必填项和规则，这条记录能不能导入。例如新系统要求每张借用单有借用日期，台账里没写日期的行就导不进去。逐行列出导不进去的行和原因，统计总数，在阶段 1 就请用户决定：补齐后导入、不导入只留原台账备查，还是按约定的默认值导入（如用途写"台账未记录"）。不要等到搭建时才发现。

**注意**：逐行核对用的是脱敏后的数据。记录较多时（几百行以上），可以写一小段脚本逐行检查，再把不符合的行列出来；不要只抽看前几行。

## 4. 提取时的注意事项

- **出现过的值不等于全部的值。** Excel 里只出现了 4 种状态，不代表只有 4 种。一定要问："还有没有其他情况，只是这段时间没遇到？"
- **列名不等于含义。** "日期"列可能是申请日期，也可能是借出日期。看不准就问，不要猜。
- **区分规则和习惯。** 某个经办人总是这样做，不一定是规则。问"这是规定，还是某某的习惯？"
- **矛盾要摆出来。** 两份材料说法不同（表单写借期 30 天，SOP 写 14 天），或者实际做法和书面规定不同，都不要自己选一个，列入矛盾清单交给用户裁决。
- **不要为了自圆其说改写材料里的事实。** 后续整理案例、规则时，如果发现和材料对不上，回到矛盾清单让用户裁决，不要改写案例或材料中的任何一方。
- **痛点也是发现。** 重复录入、手工核对、需要来回询问的地方，都记为痛点，写入 `01-as-is.md`。
- **名称先记原文。** 提取时先保留材料里的原始叫法，到 1d 统一整理进术语表，并在术语表中注明原始叫法，方便用户对照。

## 5. 输出格式

写入 `spec/01-mining.md`：

```markdown
# 材料考古结果

## 材料清单

| 编号 | 文件 | 类型 | 说明 |
|---|---|---|---|
| M1 | 借用登记表.xlsx | Excel 台账 | 前台填写，管理员每周查看 |
| M2 | 借用申请单.jpg | 纸质表单 | 借用人填写，主管签字 |

## 发现

| 编号 | 发现 | 类型 | 出处 | 待确认 |
|---|---|---|---|---|
| F01 | 借用单有状态：待审、已批、已借出、已还 | 状态 | M1 "状态"列 | 是否还有其他状态？ |
| F02 | 借期不超过 30 天 | 规则 | M2 底部说明 | 与 M3 的 14 天矛盾 |
| F03 | 逾期时填写罚款金额 | 例外 | M1 "罚款"列，仅 6 行有值 | 罚款怎么计算？ |
| F04 | 设备编号在两个表中重复录入 | 痛点 | M1、M4 | — |

类型取值：实体 / 属性 / 状态 / 角色 / 规则 / 例外 / 痛点 / 关联

## 逐行核对（核对基准日：YYYY-MM-DD）

| 记录 | 检查内容 | 结论 | 说明 | 能否导入（需要迁移时填写） |
|---|---|---|---|---|
| JY-0901 | 借期、归还 | 符合 | 借 7 天，应还 = 借用日期 + 7 天 | 能 |
| JY-0904 | 状态与日期 | 隐藏规则 | 备注"先登记，库存不够"，没有日期 | 不能：缺借用日期 → 请用户决定 |
| JY-0905 | 状态与日期 | 漏办 | 应还日期已过 26 天，仍记为"已借出" | 能 |
| JY-0908 | 拒绝理由 | 执行与规定不一致 | 以"有逾期记录"拒绝，规定只禁止"逾期未还" → X2 | 不能：缺借用日期 → 请用户决定 |

不能导入的记录共 N 条，用户决定：……

## 矛盾清单

| 编号 | 类型 | 内容 | 出处 | 用户裁决 |
|---|---|---|---|---|
| X1 | 材料之间 | 借期 30 天还是 14 天 | M2 vs M3 | （待用户回答） |
| X2 | 执行与规定不一致 | 有逾期记录但已归还，能否拒借 | M1 JY-0908 vs M3 | （待用户回答） |
```

阶段 1d 整理规则时，每条 BR 都要引用对应的发现编号作为出处，例如 `[材料: M2] (F02)`。
