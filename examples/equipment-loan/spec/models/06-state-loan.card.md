# 借用单的状态变化

![](06-state-loan.png)

## 这张图讲什么
一张借用单从提交到结束，会经历哪几种状态，以及每次变化由什么引起。

## 怎么读
- 圆角方框是状态，箭头是状态的变化。
- 箭头上的文字依次是：编号（T1–T11）、什么操作、[前提条件]、变化时顺带做的事。
- 方框里的 entry / do / exit 是进入、停留、离开这个状态时系统自动做的事。"已申请"方框里的最后一行表示：审批人同意但还有人没审批时，借用单保持已申请，只记下这次同意。
- 带圈的黑点表示借用单结束：已拒绝、已撤回、已归还。

## 用你的案例走一遍
- GC-01：已申请 → (T3 管理员批准) 已批准 → (T7 借出) 借出中 → (T8 到期) 已逾期 → (T10 归还并收费) 已归还。
- GC-02：已申请 → 管理员同意（保持已申请）→ (T3 部门负责人同意) 已批准 → (T7) 借出中 → (T9 按时归还) 已归还。
- GC-03：S-014 的新申请：已申请 → (T4 拒绝) 已拒绝；他逾期的话筒：已逾期 → (T10 归还并按上限收费 200 元) 已归还。
- GC-05：已申请 → (T3 管理员批准) 已批准。
- GC-04：已申请 → (T1 设备不足) 等待设备 → (T2 设备归还) 已申请 → (T5 撤回) 已撤回。

## 它决定了 app 的哪部分
借用单上显示的 8 种状态；每种状态下页面上出现哪些按钮；系统什么时候自动改变状态。

## 请你检查
1. 已拒绝之后借用单就结束了，借用人想再借需要重新提交。对吗？
2. 管理员取消已批准的借用单（T11）后，状态和借用人自己撤回一样显示为"已撤回"。需要区分吗？
3. 已逾期的借用单归还时一定收费，没有例外。对吗？

## 我做的假设
- 通知、提醒等 entry / do 动作由后台服务实现，不在类图中单独列出。
