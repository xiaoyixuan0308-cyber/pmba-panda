# 变更提案 001：补充取消原因和通知的存储

## 为什么改

阶段 5a 按类图建数据表时发现两处缺口：

1. 状态机 T4（拒绝）和 T11（取消）的效果都是"记录原因"。拒绝的原因可以存进审批记录（Approval）的意见里，但设备管理员取消已批准的借用单（T11）不产生审批记录，原因没有地方保存。
2. 构建计划第 4 节规定通知以系统内消息模拟，状态机中多处效果和 entry 动作会发送通知（notifyBorrower、notifyApprovers 等），但类图中没有保存通知的类。

## 改什么

- Loan 增加属性 `-closingReason: String`：取消（T11）时必填，保存原因。拒绝（T4）的原因仍保存在 Approval 的 `comment` 中。
- 新增类 Notification（通知）：接收人、相关借用单、内容、创建时间、阅读时间。

## 影响范围（按追溯矩阵）

| 产出 | 影响 |
|---|---|
| 业务规则 | 无变化（BR-04、BR-08 已要求填写原因） |
| 用户故事 | 无变化（FUS9 AC1、AC3 已要求填写原因并通知借用人） |
| 术语表 | 新增 Notification |
| 类图 | Loan 新增属性；新增 Notification 类及其与 Person、Loan 的关联 |
| 其他图 | 无变化 |
| 构建计划 | 第 1 节表结构新增 `notifications`，`loans` 新增 `closingReason` |
| 代码与测试 | 5a 按新类图建表 |

## 用户确认

这是不改变业务规则的技术补充，示例中的用户已确认。
