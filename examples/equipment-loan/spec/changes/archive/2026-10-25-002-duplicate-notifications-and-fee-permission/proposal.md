# 变更提案 002：去掉重复通知，补充设备管理员登记逾期费的权限

## 为什么改

阶段 5b 把状态机逐条翻译成转换表时发现：

1. **重复通知**：T1 的效果 `notifyBorrower` 与 Waitlisted 的进入动作 `entry / notifyBorrower` 重复；T2 的效果 `notifyManager` 与 Requested 的进入动作 `entry / notifyApprovers`（待审批人就是设备管理员）重复。照图实现，同一件事会发两条通知。
2. **权限不一致**：FUS7 AC5 规定办事员和设备管理员都可以办理归还，逾期归还时要登记逾期费已缴；但 CRUD 矩阵中只有办事员能修改逾期费（登记已缴），设备管理员只能查看。

## 改什么

- 状态机：T1 改为 `T1 review [not equipmentAvailable]`；T2 改为 `T2 equipmentReleased`。通知由进入动作统一负责。
- CRUD 矩阵：设备管理员对 LateFee 由 `R` 改为 `R、U(登记已缴)`。

## 影响范围

| 产出 | 影响 |
|---|---|
| 业务规则、用户故事 | 无变化 |
| 状态机图及说明卡 | T1、T2 标签 |
| 序列图 | 无变化（序列图中没有画这两个通知） |
| CRUD 矩阵 | 一格 |
| 构建计划 | 第 2 节转换表 T1、T2 的效果列 |
| 代码与测试 | 5b 按新状态机实现 |

另外，构建计划第 2 节 T10 的守卫误写为"逾期费已登记缴纳"（状态机图中 T10 没有守卫，效果为 chargeLateFee），属于构建计划的笔误，一并更正。

## 用户确认

不改变业务规则，示例中的用户已确认。
