# 设备借用系统（原型）

星河学院传媒中心设备借用系统的可运行原型，用来向学院领导演示、争取正式立项。

> 虚构示例：机构、人员、设备和借用记录全部虚构。需求、模型和验收标准在 `../spec/`。

## 运行

需要 Node.js 20 或更高版本。

| 命令 | 作用 |
|---|---|
| `npm install` | 第一次运行前安装依赖 |
| `npm run setup` | 建库并写入演示数据；随时重跑可以把数据恢复到初始状态 |
| `npm run dev` | 启动原型，在浏览器打开 http://localhost:3000 |
| `npm test` | 运行单元和集成测试（150 项） |
| `npm run test:e2e` | 构建后，从界面跑 5 个黄金案例 |

第一次运行 `npm run test:e2e` 前，执行一次 `npx playwright install chromium` 下载浏览器。

以构建后的方式运行（`npm run build && npm start`）时，需要设置会话密钥：把 `.env.example` 复制为 `.env.local`，填写 `SESSION_SECRET`（至少 32 个字符，文件里有生成命令）。没有设置时程序会拒绝启动。`npm run dev` 不需要。

## 演示账号

密码统一为 `demo1234`，仅用于演示。

| 角色 | 账号 | 登录后首先看到 |
|---|---|---|
| 学生（借用人 S-060） | student@demo.local | 我的借用单 |
| 教师（借用人 T-003） | teacher@demo.local | 我的借用单 |
| 办事员 | clerk@demo.local | 柜台：今天待领取、待归还 |
| 设备管理员 | manager@demo.local | 审核：待审核、等待名单、已逾期、到期检查按钮 |
| 部门负责人 | depthead@demo.local | 待我审批、本月概况 |

其他借用人账号为 `学工号小写@demo.local`，例如 S-014 是 `s-014@demo.local`（台账中有逾期未还的 JY-0905）。

## 演示控制

- **模拟今天**：演示数据以 2026-10-08 为"今天"。设备管理员在"设置"页可以改日期，再到"审核"页点"运行到期检查"，演示逾期和审批提醒。正式系统中到期检查每天自动运行。
- **资产登记系统**：是模拟的，页面上标有"模拟数据"。CAM-0013 的标签核对不通过；在设置页把"资产登记系统是否可用"改为 false，可以演示系统连接不上的情况。
- **通知**：只在系统内显示（右上角铃铛），标有"模拟通知"。

演示步骤见 `../spec/06-demo-script.md`。

## 功能和用户故事

| 页面 | 用户故事 |
|---|---|
| 提交申请（手机可用） | FUS1、NFUS5 |
| 我的借用单、借用单详情（撤回、签协议） | FUS2、FUS6 AC4 |
| 审核页：逾期和库存两项检查、批准、拒绝、转入等待名单 | FUS3、FUS4、FUS8 |
| 柜台：借出（核对资产标签）、归还（计算逾期费） | FUS5、FUS7 |
| 审核首页：等待名单、已逾期、运行到期检查 | FUS6、FUS8、FUS10 |
| 取消已批准的借用单 | FUS9 |
| 借用统计 | FUS11 |
| 设置：逾期费单价和上限、提醒工作日数 | NFUS6 AC2 |
| 借用单详情：操作历史 | NFUS2 |
| 全部借用单：查找和分页 | NFUS4 |

每条验收标准对应的测试见 `../spec/trace.csv`。

## 目录

```
src/
  db/            表结构（来自类图）
  rules/         决策表 DT-01、DT-02（写成数据）
  domain/loan/   状态机转换表、唯一的状态变更函数、守卫、业务操作、每日检查
  auth/          权限表（来自 CRUD 矩阵）、登录和会话
  adapters/      资产登记系统接口和模拟实现
  app/           页面
scripts/         建库和演示数据
tests/           unit / integration / e2e
drizzle/         数据库迁移（含操作记录只能新增、借用单不能删除的保护）
```
